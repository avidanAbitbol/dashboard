# CENT — התראות טלגרם

ניטור המטבע הראשי CENT ברשת Incentiv (chain ID 24101). סף התחלתי: **מעל 10,000 CENT להעברה בודדת**. בודק העברות רגילות ופנימיות, מוודא הצלחת העסקה וממתין ל־12 בלוקים נוספים. רשימת הארנקים ופרטי הטלגרם אינם כלולים בקוד.

## התקנה חד־פעמית

1. העלו את תוכן התיקייה למאגר GitHub ציבורי בענף ברירת המחדל, כולל `.github/workflows/monitor.yml`.
2. בטלגרם צרו בוט דרך [BotFather](https://t.me/BotFather), פתחו איתו שיחה פרטית ושלחו `/start`. שמרו את הטוקן באופן פרטי.
3. ב־GitHub פתחו Settings → Secrets and variables → Actions והוסיפו **Repository secrets**:

| שם | ערך |
| --- | --- |
| `WATCHED_WALLETS` | תוכן רשימת הארנקים, כתובת בכל שורה. אין להעלות את הקובץ עצמו למאגר. |
| `TELEGRAM_BOT_TOKEN` | הטוקן מ־BotFather |
| `TELEGRAM_CHAT_ID` | המזהה המספרי החיובי של השיחה הפרטית עם הבוט |
| `STATE_KEY` | מפתח אקראי של 32 בתים בקידוד Base64 |

ליצירת מפתח במחשב עם Node: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. העתיקו ישירות לסוד; אל תפרסמו אותו. לקבלת מזהה השיחה אפשר לקרוא מקומית את `getUpdates` של Telegram לאחר שליחת `/start`; אין לשלוח את הטוקן לשירות צד שלישי.

4. באותה לשונית, תחת **Variables**, הוסיפו `CENT_THRESHOLD` בערך `10000`, ו־`ENABLE_MONITOR` בערך `true`.
5. פתחו Actions → CENT Telegram monitor → Run workflow, סמנו `initialize` והפעילו פעם אחת. הודעת הפעלה אמורה להגיע לטלגרם. ודאו שהריצה ירוקה ושה־artifact בשם `cent-state` נוצר.

**הקוד לבדו אינו מפעיל שירות.** נדרשים המאגר, הסודות והריצה הראשונה. הבוט לא קורא פקודות טלגרם; שינוי הסף נעשה ב־GitHub Variables ונכנס לתוקף בריצה הבאה. רק סכומים גדולים ממש מהסף נשלחים; 10,000 בדיוק לא שולח התראה. שינוי הסף לא מריץ מחדש היסטוריה, אך עשוי להשפיע על חלון החפיפה האחרון ועל התראות ממתינות.

## שימוש ותחזוקה

- בדיקה מתוכננת כל חמש דקות, גם כשהמחשב כבוי. GitHub עשוי לעכב או לדלג על ריצות; אין הבטחת זמן אמת או זמינות 24/7. מאגר ציבורי ללא פעילות במשך 60 יום עשוי לאבד את התזמון — יש לבדוק ולהפעיל מחדש לפי הצורך.
- לעצירה: שנו `ENABLE_MONITOR` ל־`false`. ההתקדמות מוצפנת ונשמרת ב־artifact למשך יום; עצירה ארוכה יותר עלולה לחייב התחלה חדשה ללא כיסוי התקופה שאבדה. אם אין מצב שמור, הבוט נעצר ולא מאתחל את עצמו אוטומטית.
- התחלה מחדש בלי state: ריצה ידנית עם `initialize` מתחילה מעכשיו. היא אינה משחזרת את התקופה החסרה. מפתח שגוי/אובדן מפתח או מצב פגום מחייבים תיקון; אין למחוק מצב לצורך פתרון שגיאה בלי להבין את אובדן הכיסוי.
- נשלחת הודעה אחת לכל עסקה עם עד ארבע העברות שונות מעל הסף. העברות נוספות מופיעות בקישור לסייר. אין חיבור סכומים קטנים יחד. בהעברה בין שני ארנקים במעקב לא נשלחות שתי הודעות.
- עמלת הרשת אינה נכללת בסכום. תשלום נפרד למממן GAS דרך העברה אמיתית עדיין עשוי להופיע אם הוא מעל הסף; זה אינו סיווג כלכלי של מטרת ההעברה.
- קיימת חפיפה של שעה לסריקות. אינדוקס מאוחר יותר משעה עלול שלא להיתפס. מידע פנימי מסתמך על הסייר; אימות RPC מוודא הצלחה ובלוק קנוני, אך אינו מאמת מחדש כל trace.
- מוגבל ל־20 הודעות בריצה; היתרה נשמרת. בעת עומס זמן ההשלמה מתארך. אחרי כשל בין שליחת Telegram לשמירת ה־artifact תיתכן הודעה חוזרת. אין הבטחת exactly-once.
- בדקו כשלי Actions והפעילו הודעות כשל של GitHub. כשהתזמון מפסיק, הבוט עצמו לא יכול להודיע על כך.

## עלות ופרטיות

ה־workflow משתמש ב־runner סטנדרטי של GitHub Actions ומסרב לרוץ במאגר פרטי. לפי [GitHub](https://docs.github.com/en/actions/concepts/billing-and-usage), השימוש ב־runners הסטנדרטיים במאגרים ציבוריים חינמי. אין שירות בתשלום בקוד; יש לבדוק גם מכסות אחסון כוללות של החשבון ולא לאפשר חיוב חריגה. מצב נשמר מוצפן עד יום אחד, עם מגבלת 1.5MB לקובץ. [מגבלות התזמון](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

הקוד ציבורי, ונתוני המעקב נשמרים בסודות וב־AES-256-GCM. מי שמחזיק במפתח יכול לפענח את ה־artifact. אין לרשום סודות בלוגים או בקבצי המאגר. הנתונים נשלחים לסייר/RPC לצורך הבדיקה ולטלגרם לצורך ההתראות. אין צורך במפתח פרטי של ארנק, seed phrase או חתימה.
